# ADR-0002: "World State" replaces "Context"; horizontal services replace pipeline stages

> Status: Accepted · Date: July 2026

## Context

architecture.md v0.1 used "Context" for temporary environmental information
and "Memory" for persistent information, while the domain model and planner
documents used "World State" for the same observed-environment concept. Two
names for one concept is exactly the terminology drift the domain model was
written to prevent. Separately, v0.1 drew shared systems (Tool Registry,
Safety) as stages in the request pipeline, implying requests flow through
them at runtime.

## Decision

1. **"Context" is retired as a noun across the repository.** The pair is:
   - **World State** — observed, timestamped, volatile facts about the
     environment, produced by Observation.
   - **Memory** — interpreted, persistent knowledge, produced by Learning
     and user statements.
   ("Planner context" survives only as an informal phrase for the assembled
   snapshot-plus-memory input to planning; no system or document may be
   named Context.)

2. **Shared systems are horizontal services, not pipeline stages:**
   World State, Memory, Tool Registry, Safety Policy Engine, Sessions,
   Learning. Stages consult services; services never consult stages;
   service-to-service edges are individually declared (currently:
   Learning → Memory, Safety → Tool Registry).

## Consequences

- vision.md and all future documents must use World State/Memory
  vocabulary; the "Knowledge System" section of architecture.md v0.1 is
  superseded.
- Safety moves from a pipeline checkpoint to a policy engine consulted per
  action at dispatch time.
- The Tool Registry is consulted by the Compiler (compile time) and
  Executors (dispatch time); it is never a runtime router.
- The service dependency rule becomes an architectural invariant enforced
  in review.
