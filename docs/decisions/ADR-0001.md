# ADR-0001: Replace "Intelligence System" with "Goal Builder"

> Status: Accepted · Date: July 2026

## Context

The v0.1 architecture defined three systems co-owning "understanding the
user": Conversation (NLU, reference resolution), Intelligence (intent,
ambiguity, confidence), and Planning ("request clarification when needed").
Co-ownership of understanding meant no single owner, and "Intelligence" as a
name was unfalsifiable — every component in an AI product can claim it.

## Decision

Replace the Intelligence System with a **Goal Builder** whose sole output is
a well-formed Goal object.

- **Conversation** owns dialogue: turns, history, reference resolution.
- **Goal Builder** owns producing valid Goals, including detecting
  ambiguity and missing information. When clarification is needed, the Goal
  Builder asks — routed through Conversation and Presentation.
- **Planner** consumes only valid Goals and never interacts with the user
  directly.

## Consequences

- The pipeline gains a quality gate: ambiguity cannot reach the Planner.
- Systems are named after their outputs, which makes responsibility
  checkable in review ("does this code build Goals?").
- The Goal object needs a precise definition (planner/domain-model.md,
  planned): what makes a Goal "well-formed" is now a real contract, not a
  vibe.
- Clarification loops add latency before planning begins; acceptable, since
  a wrong plan is more expensive than a question.

## Alternatives Considered

- **Fold intent-building into the Planner as an intake phase.** Fewer
  boxes, but re-couples user dialogue to the Planner, violating "the
  Planner never talks to the user." Rejected.
- **Keep "Intelligence System" with tightened responsibilities.** The name
  invites scope creep; rejected on naming grounds alone.
